# 05 多站点与免登录增强：尝试后放弃（⏸ 2026-11-27）

> 类型：发现 / 实施尝试 ｜ 状态：⏸ 放弃 ｜ 结论：产品只做 **DeepSeek 单站**，`1.0.0` 即最终形态，原计划的 `1.1.0` 取消。

## 当时的目标

把单站 DeepSeek 面板扩成多站（DeepSeek / 千问 / Gemini / 自建），每站独立登录快照，目标「登录一次、同机重启免登录」。

## 做了什么

- **P1–P5**（本地 commit `5e4edfb`…`0311ce2`）：站点表 v2、每站一个 guest 与主面板、左栏一站一行、站点编辑器 / 图标 / 页面保活、文案与文档。
- **P6 冷启动实测**（2026-11-27，正常启动、无调试端口）：DeepSeek 免登录成立；千问可读存储（21 cookie + 30 localStorage 键）全部回填后仍要求登录。
- **P6.5-A 落点对照**（2026-11-27，调试端口只读取证，不打印值）：登录新增的关键票据 `tongyi_sso_ticket` 是 **HttpOnly**（`.qianwen.com`、Secure、SameSite=None、1 年）；登录没有新建 IndexedDB 库，只多了缓存/日志写入。
- **决定性对照**：只删 `tongyi_sso_ticket`、保留其余全部可读状态（22 个可读 cookie、40 个 localStorage 键、3 个 IndexedDB 库）→ 刷新后立刻回到未登录；站点不会用可读的 `tongyi_sso_ticket_hash` 自动续签。

## 为什么放弃

- HttpOnly cookie 按浏览器安全模型对页面 JS **不可读也不可写**，插件内无法快照/回填；Cookie Store API 同样拿不到。
- cookie 属性保真（domain / expires / SameSite）只能修可读 cookie，救不了票据本身；IndexedDB 快照没有凭据可存。
- 要做到跨重启免登录，只能改 DSH（持久化 guest session）或逆向站点私有 API 换票，均超出「不改 DSH、可安装即用」的红线。Gemini 同类。

## 回退

- 本地 `main` 已回到 `origin/main`（`a8a0d1a`，V1 单站、`v1.0.0` 之后的文档收口），工作区干净。
- 多站尝试的 14 个本地 commit 保留在**本地分支 `archive/v2-multi-site`（未推送）**；远端 `main` 与 `v1.0.0` tag 未受影响。
- 用户数据：站点表 v2 会被 V1 的 `ensureSites()` 重写为单站；DeepSeek 快照结构不变，登录保留。千问 / Gemini 的快照键变为孤儿，可在设置页清除。
- 对照数据（只有名称/属性/计数，不含值，不入仓）：本地 `.dsh-pilot/p65a-*.json`。

## 如果将来再试

先解决「guest 的持久化 session / 跨重启 cookie」：需要 DSH 桥暴露持久分区，或站点提供**可读**的长期令牌；否则会是同一结论。
