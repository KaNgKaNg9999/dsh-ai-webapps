## 任务清单

### V1 — `[aiwa]` console 转发（guest → 宿主 DevTools）

- **是什么**：guest 的 console 经 Electron `console-message` 转发到主窗口 DevTools，前缀 `[aiwa][guest]`，级别 3→error / 2→warn / 其余→log（`client.js` `forwardConsole`，事件绑在 `wireGuest`）。打包版 guest DevTools 关闭，这是唯一排障窗口。
- **操作**：
  1. 主窗口打开 DevTools（Ctrl+Shift+I）。
  2. 打开 DeepSeek 面板，等页面加载完。
  3. 在宿主 DevTools 里执行探针：
     `document.querySelector('webview').executeJavaScript('console.warn("aiwa-console-probe")')`
  4. 看 Console 是否出现 `[aiwa][guest] aiwa-console-probe`，且用的是 warn 级别。
- **通过判据**：探针日志出现且前缀/级别正确；站点自身日志同样带 `[aiwa][guest]`。
- **失败处置**：核对 `console-message` 负载（`level` 数字/字符串两种都已在代码兼容）；若事件根本不触发，改为在关键失败分支（`did-fail-load`、注入失败、校验失败）主动 `runInGuest` 取错误并打印 → 重验。
- **注意**：宿主侧 `[aiwa] snapshot saved; keys=…` 不能作为本项证据。

### V2 — Turnstile 是否触发（新机首次登录路径）

- **是什么**：DeepSeek 登录页的 Cloudflare Turnstile。设计分支 R5：先裸测；被拦则切 `webview.setUserAgent(纯 Chrome UA)` 再试；仍失败记录为站点侧限制。按 R11 默认不启用 UA 覆盖（**当前 `client.js` 无任何 UA 覆盖代码**，是刻意未实现）。
- **操作**：设置页「清除已保存登录」→ 面板退回登录页（必要时彻底退出重启）→ 正常走手机号/密码登录，记录：是否出现 Turnstile、是否通过、是否需重试。
- **通过判据**：登录成功，且记录「Turnstile 是否出现」写进 `spec §10`（放行 = 本项通过，R5 不实现）。
- **失败处置**：若挑战无法通过 → 实现设置项「使用标准 Chrome UA」（默认关，`createGuest` 前 `setUserAgent`），设置页写明副作用（client hints、站点实验开关），记录为站点侧限制 + 开关可自救；重验。
- **代价提示**：本项会消耗真实登录一次。

### V3 — `stale` 快照降级（防回填死循环）

- **是什么**：快照失效后的降级。两个入口：回填后 1.2s 校验失败（token 键消失 / 仍在登录路径）→ `markSnapshotStale()` + 工具栏提示「登录已失效，请重新登录」；下次启动读到 `stale` 直接不回填（`validateBackfill` / `maybeBackfill`）。设计来源 R2。
- **操作（安全、可回滚）**：
  1. 先备份快照值到本机临时笔记（**不得贴进仓库/日志/文档**，含 token）：
     `localStorage.getItem('dsh-ai-webapps.snapshot.v1')`
  2. 改坏 token：
     ```js
     const s = JSON.parse(localStorage['dsh-ai-webapps.snapshot.v1']);
     s.sites.deepseek.localStorage.userToken = 'broken';
     localStorage['dsh-ai-webapps.snapshot.v1'] = JSON.stringify(s);
     ```
  3. 彻底退出 DSH → 重启 → 打开面板，观察三点：**不出现循环刷新/闪屏**；工具栏显示「登录已失效，请重新登录」；设置页胶囊变红「已失效」。
  4. 单独验「启动不回填」：把 `s.sites.deepseek.stale = true` 写回 → 重启 → 应直接停在登录页、Console 无注入日志。
  5. 验完恢复备份 → 重新登录一次 → 快照重新采集、`stale` 清除、胶囊回绿。
- **通过判据**：上述 3/4/5 全部符合；`[aiwa] backfill did not restore the sign-in` 只出现一次、不重复。
- **失败处置**：`markSnapshotStale` 落盘失败时改内存标记兜底；校验失败改为「清空快照 + 提示」（更彻底，用户需重登）；确认 stale 分支不 emit `restoring`、不重放注入。

### V4 — `render-process-gone` 自动重建

- **是什么**：guest 渲染进程崩溃/被杀 → `crash()`：crashes+1、显示「页面已崩溃，正在重建…」→ 拆 webview + release 旧 lease → 600ms 后重新 acquire 新 lease 建新 webview → 快照回填恢复；连续 >3 次停手等手动刷新。每个 lease 只能 attach 一次，所以旧 lease 不可复用。
- **操作 A（真崩溃注入，首选）**：宿主 DevTools 里执行
  `document.querySelector('webview').executeJavaScript('location.href="chrome://crash"')`
- **操作 B（备选：合成状态机测试）**：若 A 被导航守卫拦截，把 `crash()`/`teardown()` 的决策抽成可测纯函数，用 `node --test` 覆盖：`active`/`suspended`/`disposed` 守卫、600ms 重启延迟、>3 次停手、重建使用**新 lease**、卸载中不重建。
- **通过判据（A）**：出现崩溃卡片 → 约 600ms 后回到加载卡 → 自动进聊天页且**无需重新登录**（快照回填成功）；`[aiwa] guest attached; lease=…` 出现新 lease；旧 lease 有 release 记录。判据（B）：测试全绿且覆盖上述分支。
- **失败处置**：修正 `teardown` 释放顺序（先解事件/移除元素再 release）、旧 lease release 失败要容忍并继续新 lease、attach 被拒时重试；补「重建次数用尽」明确文案 + 手动刷新入口。
- **注意**：注入会打断当前 guest，登录态靠快照恢复——先确认 V3 通过再做本项。

### V5 — `shell.overlay` 与 body 弹窗遮挡关系

- **是什么**：guest 容器在 `shell.overlay`（`.overlayLayer`，`z-index:20`、点击穿透、直接子元素 `pointer-events:auto`）；宿主弹窗在 body 层。代码侧两道保险：容器自身 `z-index:1`；监听 `[inert]`，弹窗给 `#root` 置 inert 时 suspend（blur + 隐藏）。
- **操作**：依次打开 ① 设置 ② 命令面板 ③ 删除会话确认框 ④ 插件页插件详情 ⑤ 侧栏展开菜单 ⑥ 任意 Markdown 预览浮层。每项看三件事：弹窗完整可见、可点击、关掉后 DeepSeek 面板恢复可见可交互、焦点不在 guest。
- **通过判据**：六类弹窗全部满足；设置项在 M0-E 已过，其余五类为本次新增观察。
- **失败处置**：容器 `z-index` 降至层内最低，或加「出现 `[role="dialog"]` 即 suspend」的兜底（注意别误伤站点自身弹窗——站点 alert/confirm 已被 deny，弹窗一律走系统浏览器）。

### 取证手段的变化（2026-11-27）

宿主 DevTools 不可用后，改用两种不依赖 DevTools 的手段，均已验证可行：

1. **`--remote-debugging-port=9222` + `tools/cdp-eval.mjs`**：给 DSH 加调试端口启动，脚本用 CDP 在宿主渲染进程执行 JS、订阅 console。V1 的全部取证、V3 的快照破坏与恢复都靠它。
2. **外部杀掉 guest 渲染进程**：不打补丁就能触发真实的 `render-process-gone`，取代被拦下的 `chrome://crash`（`Not allowed to load local resource`）。guest 渲染进程可用「让 guest 自己烧 CPU、比对进程 CPU 时间增量」精确认出（实测 guest +2,969ms vs UI +375ms），不必靠猜。

### V3 stale 降级 — 通过（含一处修复）

用「页内备份 → 改坏 token → 强制新 lease」复现，替代原计划的「改快照 + 重启」；两者走的是同一个 `maybeBackfill`/`validateBackfill` 代码路径。

| 步骤 | 实测 |
|---|---|
| 注入 | `[aiwa] snapshot injected; localStorage=29 cookie=2` |
| 校验 | `[aiwa] backfill did not restore the sign-in (still on /sign_in); snapshot marked stale`（只出现一次） |
| 落盘 | `snapshot.stale === true` |
| UI | 工具栏显示「登录已失效，请重新登录」；页面停在登录页，**无循环刷新/闪屏** |
| 采集保护 | `[aiwa] snapshot skipped; guest is on the sign-in path`（不覆盖好快照，R3 成立） |
| stale 生效 | 新 lease 下**没有** `snapshot injected`，正确地不再回填 |

**修复（本次发现）**：`validateBackfill()` 原来只判断「token 键是否存在」。注入一个**值已损坏但键仍在**的 token 时，校验会误判成功 → 永不标 stale、永不给提示，每次新 lease 都白注一次。改为**同时判断探针已返回的 `login` 标志**（`client.js:570`），并对「有 token 但仍在登录路径」加一次 1s 复核，避免把站点跳转中的有效会话误判。

### V4 崩溃重建 — 通过（含一处修复）

| 场景 | 实测 |
|---|---|
| 面板可见时崩溃 | `guest gone: render-process-gone: unknown` → 600ms 后 `guest attached; lease=0f3aea31-…`（**新 lease**）→ `sign-in already present; skip backfill`（无需重登）→ 回到聊天页 |
| 面板不可见时崩溃 | 只有 `guest gone`，不重建（符合设计：不打扰、省资源） |
| 切回面板后 | `guest attached; lease=eee45037-…`（再次全新 lease）→ 自动恢复，免重登 |

**修复（本次发现）**：`maybeStart()` 的门是 `state.phase !== 'idle'` 就返回，而崩溃后 phase 停在 `'crashed'` → 面板切走时崩溃会跳过重建，切回来时**永远重建不了**，卡片却写着「正在重建…」，且重试按钮只对 `failed` 态出现（`client.js:1286`）→ 用户无路可走。改为：`maybeStart` 放行 `crashed`；重建次数用尽时置 `stopped` 标记，卡片改文案为「自动重建已停止，请手动刷新」并给出按钮；`start`/`reload` 清标记。
