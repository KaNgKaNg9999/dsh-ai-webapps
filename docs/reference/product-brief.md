# 产品简报（Product Brief）

> 状态：定稿（2026-11-26）｜最后更新：2026-11-26
> 只记录已确认的结论；未决项用「未决」格式，不写裸待办。

## 问题

在 DSH 桌面端和浏览器之间来回切换使用网页版 AI 聊天（主力：Gemini / DeepSeek / Grok），每次提问都要切窗口、切输入焦点，打断写代码与排障的节奏；DSH 内置的右侧栏浏览器虽然能开网页，但需要手输 URL、不是满宽主面板，且登录态重启即丢。

## 用户与场景

- 用户：项目作者本人（单用户；Windows 桌面端 DSH 用户）。
- 场景：写代码或排障时随手向 DeepSeek 提问 → 切回会话继续 → 下次开机不重复登录。
- 现状/替代方案：① DSH 内置右侧栏 Browser（手输 URL、非满宽、登录不持久）；② 切到系统浏览器（离开 DSH）；③ 已废弃的 v1 插件（每次启动改 `app.asar`、搬运 Cookies 文件，导致 EBUSY 与冷启动崩溃，已清理）。

## 范围

- 第一版必须：左栏一个 DeepSeek 站点行；点击进入主面板全宽聊天（Electron `<webview>`）；切到会话再切回**不重载**（草稿/滚动保持）；登录一次后**同机重启自动登录**；设置页显示登录保存状态并可清除。
- 明确不做：站点增删/排序（V1 固定单站）；登录态导出/导入；Gemini / Grok；任何 `app.asar` 改动；登录态跨机迁移；通用浏览器能力。
- 以后再做：~~多站（先千问）；站点管理 UI；Gemini / Grok 适配~~（2026-11-27 试做后放弃，见 `docs/plans/05-多站点尝试与放弃.md`）；登录态迁移（需评估设备指纹风险）。

## 成功标准

- 验收场景（M0 六条，全过才算第一版）：
  1. 左栏出现 DeepSeek 行，点击后主面板选中并渲染工具栏与面板；
  2. webview 成功加载 `chat.deepseek.com`（`console-message` 转发可见）；
  3. 能完成登录（手机/邮箱 + Turnstile；失败时走 UA 覆盖分支再试）；
  4. 切到会话再切回：不重载，草稿与滚动位置保持，guest 未重建；
  5. 登录后打印 `Object.keys(localStorage)`（仅键名）核对 token 键；
  6. 托盘彻底退出 → 重启 → 自动登录，且启动不会自动停在站点面板。
- 指标：V1 只做人工验收；后续可记录"点击到可输入"的耗时与重登频率。

## 非目标

- 不做账号体系、不做计费/额度展示、不做对话内容抓取或转发给 Agent。
- 不做站点内功能改造，不代理/改写站点流量。
- 不替代 DSH 已有的模型接入能力（本项目只提供"网页版"入口）。
